## Source and application boundaries

Implemented development changes include central resource ownership, private document/PDF input and renderer restrictions, warranty owner scoping, locally versioned BPAN contracts, permanent device revocation, bounded reading contracts, numerical unit corrections and default-off unsupported actions. The authenticated local-pilot RPC/page/REST and generic incident router are actually mounted. `createAlert` returns its inserted alert and awaits generic incident enqueue in the same transaction; declined-provider rows/code are retained inactive, not reinterpreted or replayed.

Every current alert producer lacks the trusted live-critical acquisition context, so existing alerts remain nonpaging. A token holder declaring `BMS_REPORTED`, HTTPS transport or a software receipt does not authenticate physical hardware provenance. The new pilot remains owner-only even for administrators. Reading/acknowledging an alert, silencing Alertmanager or losing a heartbeat never establishes recovery or resolves a physical incident.

Unsupported checkout/settlement and other unsafe operations are intentionally disabled. Before releasing a change that rejects old payment webhooks, inventory previously created checkout/payment records and establish accountable manual reconciliation and retry handling. The current webhook rejects non-success rather than acknowledging unprocessed money events. This avoids false success but does not preserve indefinite provider retry or prove completed settlement. Do not release into unresolved in-flight real-money obligations.
